## What a hand-made highlight looks like (3 made in the reader; the template for our writes)
| Field | Observed |
|---|---|
| `xPath` / `endingXPath` | Element paths relative to the page, e.g. `//body/p[7]`, or `//body/p[9]/span[1]`. **No character offsets.** The index counts `<p>` elements on the page as `book-page` returns them. |
| Selection starting mid-paragraph | Still stored as the whole paragraph path (`//body/p[7]` to `//body/p[8]`), with `selectedText` holding the exact words and `highlightCount` their length (309). The reader finds the words by text. |
| `selectedText` | Exact selected string (can span paragraphs, includes `\n\n`). |
| `comment` | **Quill delta as a JSON string**: `{"ops":[{"insert":"test note\n"}]}`. An annotation with no note stores `{}`. |
| `containsSpoiler` | Boolean, set by the owner (`true` on the second highlight). |
| `context` | The surrounding paragraph text (UI-made). API-made annotations have `context: null` and still render. |
| `pageNumber`, `chapterTitle` | Page index and chapter ("Chapter 10"); ids come from the series. |
| Required extra fields | `ownerUserId`, `ownerUsername` (else 400 "missing required properties"). |

## Edge cases (E12, E5)
| Case | Kavita's answer |
|---|---|
| Empty `selectedText` (E12) | **400** "Failed to create annotation". Highlight-less bookmarks cannot be stored; the hub must put a short text snippet (the sentence at the position) in `selectedText`. |
| End path before start path | Accepted (200), no validation. |
| Paragraph that does not exist (`p[99]`) | Accepted (200), no validation. It would sit invisible in the series list. |
| Two paragraphs | Accepted; fine. |
| Range across a page boundary (E5) | Not representable: paths are per page and `pageNumber` is a single number. Split into one annotation per page, or anchor at the start. |

## Consequences for the build
1. **KOReader to Kavita:** KOReader gives character offsets in an xpointer. Kavita wants the paragraph path plus the exact text. The Kavita spoke converts: xpointer to paragraph index `p[N]` (and `span[k]` when the text sits in a span), plus the quoted text. The round trip back uses the quote (E10 anchors), not the path.
2. **The hub must validate before writing:** the paragraph exists on that page, start is not after end, the text is non-empty and actually inside that paragraph. Kavita will not check.
3. Notes are Quill deltas, so notes from KOReader (plain text) are wrapped, and notes from Kavita are unwrapped to plain text (formatting lost on the way to KOReader; R9 keeps the full original).
4. **Dedupe on re-sync:** `id` is assigned by Kavita; keep a mapping from the hub annotation key to the Kavita id so edits update rather than create.
