# S6: Fable login and progress write (2026-11-10)

Script `spikes/s6_fable.py` (Python port of ShelfSync's `fable/api.lua` calls), result `S6.json`. The Fable account is the owner's; the owner approved putting one book on the shelf.

## What worked
| Step | Call | Result |
|---|---|---|
| Login | Firebase `verifyPassword` (the public web key that ships in Fable's own client), then `Authorization: JWT <idToken>` | 200 |
| Profile | `GET /api/settings/profile/` | 200, gives the user id |
| System lists | `GET /api/v2/users/{uid}/book_lists?media_type=book` | `current_reading`, `want_to_read`, `finished`, `did_not_finish` |
| Search | `GET /api/books/search/?auto=<text>&include=out_of_catalog&type=book` | 200; several editions of *This Is How You Lose the Time War* come back, all with the same title, so the hub needs a pick rule (author plus ISBN when available) |
| Shelve | `POST /api/v2/users/{uid}/book_lists/book` with `type: multiselect`, the target list, and the other three lists in `exclude_from` | 200; book now on "Currently Reading" |
| Write progress | `POST /api/books/{id}/reading_progress` with `current_percentage`, `selected_mode: percentage`, `social_accounts: []` | 201; the response body already echoes the stored progress |
| Read back | `GET /api/books/{id}/reading_progress` | `{"current_percentage":12,"current_page":24,"page_count":208,"status":"reading","selected_mode":"percentage"}` |
| Idempotent re-post | same body again | 201, value unchanged (12) |

## Findings
1. **The viewer's progress is at `/reading_progress`**, not in the book detail (which carries only `status` and `page_count`) and not in the shelf listing.
2. Fable converts a percentage into a page using the edition's `page_count` (12 % of 208 = page 24). The hub should send percentages and let Fable derive pages.
3. **Re-posting the same percentage is safe**, so the Fable writer can be debounced and retried without side effects.
4. The shelf listing entry carries no progress (`source`, `favorite`, `sort_value`, `note`, `note_visibility`, `paperclip_style`).
5. Not covered: finish dates, re-reads and a "finished" write (H7/H8). The progress object has no date fields; finishing was not tested because it would change the owner's real shelf history. Decide with the owner before testing.
6. ToS risk (unofficial API) accepted by the owner earlier.
