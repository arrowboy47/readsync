# S8: On-device anchor resolution (2026-11-10)

Result: PASS. 20/20 passages resolved to exact text on the Kindle Paperwhite 3 (KOReader v2026.07.2), live apply works.

Test plugin: `spikes/s8/readsync_spike.koplugin/` (menu: More tools, Readsync spike). Passages: `spikes/s8/samples.json`, made by `spikes/s8_make_samples.py` from *Time War* (seed 8). Raw device output: `S8.json`. Run time for all 20: under 1 second.

## Method
For each passage the plugin calls crengine `findAllText(quote)`, keeps hits inside the expected spine fragment (`/body/DocFragment[spine_index+1]`), and reads the text back with `getTextFromXPointers(pos0, pos1)`. A sample counts as exact when the text read back equals the stored quote after removing soft hyphens, non-breaking spaces and extra whitespace. This is a text check, not a comparison with a hand-made highlight (no manual highlight was made).

## Results
| Group | Count | Exact |
|---|---|---|
| Plain text | 11 | 11 |
| Smart quotes | 3 | 3 |
| Dashes and ellipses | 3 | 3 |
| Italics (span crossing) | 3 | 3 |
| Soft hyphen inside the quote | 2 | 2 (1 needed the fallback) |

No passage had more than one hit inside its fragment. Passages were chosen with the groups overlapping, so the rows add to more than 20.

## Findings
1. **Soft hyphens break a direct search.** First run: 19/20. The miss was a quote ("or canines, ...") whose word has a soft hyphen in the book ("can-ines") while the stored quote has none. crengine's search does not match across it. This is real E6, and Kavita and other readers will store quotes without soft hyphens.
2. **Fallback works.** Search the first 3 words and the last 3 words separately inside the fragment, join start of the first with end of the last, then verify the joined text equals the quote. Second run: 20/20. The fallback handles a soft hyphen in the middle only. One in the first or last few words is not covered (the plugin retries with 2 then 1 words). Passages that still fail must be parked and alerted, never guessed (R-rules).
3. **Smart quotes, dashes and italics need no special handling** in this book.
4. **Live apply (A16) works.** Adding the highlight to the open book through `ui.annotation:addItem` plus an `AnnotationsModified` event showed the highlight immediately on screen, with no reopen. Removal through `ui.highlight:deleteHighlight` also worked.
5. **Speed is not a concern.** The search over the whole book takes well under a second.

## Not covered
- Quotes that appear more than once in one spine file (prefix and suffix disambiguation not exercised, no duplicates in this sample).
- Books with different structure than *Time War*; PDFs (not supported by this path).
- A comparison with a manual highlight made on the device.
- The Kobo (different KOReader version). Re-run the same plugin there before Phase 3.

## Consequences for the build
- The KOReader side resolves anchors with `findAllText` limited to the spine fragment, with the first/last-words fallback.
- Prefix and suffix are still needed for duplicates; add a test with a repeated phrase before relying on it.
- Highlights can be pushed into an open book on the Kindle and appear at once, so A16 holds on this device.
